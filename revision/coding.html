DPORDER: which direction do you fill, and the three loop rules for coins and knapsack?

If dp[i] uses smaller indices, fill forward; if it uses larger (suffix DPs), fill backward; 2-D fills row by row. Two rules that matter for coins/knapsack:

  • Reuse allowed (unlimited coins): iterate amounts forward within a coin.
  • Each item once (0/1 knapsack): iterate amounts backward so the item is not reused.
  • Counting: order matters (permutations) → amount loop outside, coins inside; order does not matter (combinations) → coins outside, amounts inside.

Tree DFS: the five questions (6)

The DP six lines for trees. Before any tree recursion, write HAND UP, EMPTY, BUILD, SAVE, ORDER as comments, and PASS DOWN as a sixth when the node needs something only its ancestors know; the SAVE test decides whether a global exists.

TREE DFSThe five questions, plus PASS DOWN when needed, to answer as comments before any tree recursion? 
HAND UP   what one value does this node give its parent? (a number or bool, in words)
EMPTY     what does a missing child hand up?
BUILD     how does the node make its hand-up value from the two children's values?
SAVE      can the answer use BOTH my sides at once (up one child, through me, down the other)?
          the parent cannot extend such a path, so compute it here and keep the best in a global;
          hand up only the straight line, node -> child -> grandchild down one side
ORDER     post-order (left -> right -> node) when the node needs the children's values, almost always;
          pre-order (node -> left -> right) when the node decides or passes something down first;
          in-order (left -> node -> right) on a BST, which visits the values sorted
PASS DOWN (the sixth line, only when needed) what must the parent tell the child?

Everything rests on one fact: a path is a single line, it never forks. Each node hands one value up to its parent, and the parent can only use that value by continuing the line upward. So the hand-up value must describe a straight line that ends at the node.

Remember by. five words asked of the node, in order: what goes up, what if empty, how to build it, what to save (a path using both my sides at once), who goes first.

TREE DFSSAVE: when does a tree answer need a global, and what is the one-sentence test?

Some answers are not straight lines. They come up from one child, pass through the node, and go down into the other child, like the shape ∧ with the node at the top. The parent cannot continue such a shape, because continuing it would mean entering the node twice. A node can therefore have two numbers: the straight-line value it hands up, and the full answer at this node, which it saves in a global because nobody above can use it.

The test for SAVE is one sentence: “could my parent continue this value as a single line?” If yes, hand it up. If no, save it.

Diameter and Max Path Sum are the same problem with different weights, every edge worth 1 instead of node values.

TREE DFSMaximum Path Sum derived from the five questions, not memorised?
  • HAND UP: the best sum of a straight line that starts at this node and goes down one side.
  • EMPTY: 0, an empty arm adds nothing.
  • BUILD: node + max(left arm, right arm), with any arm below 0 treated as 0 (a negative arm only lowers the sum, so the path skips that side).
  • SAVE: node + left arm + right arm, the ∧ path with its top here; compare with a global best that starts at the root value, never at 0, because a single node is a valid path.
  • ORDER: children first.

TREE DFSPASS DOWN, the sixth line: how do you know a problem needs it, and what travels down?

When PASS DOWN exists. Ask: “to decide its own answer, does this node need something only its ancestors know?” If everything it needs is inside its own subtree, there is no sixth line (Max Depth, Same Tree, Diameter). If the answer depends on what is above, the parent hands it down: the allowed range in Validate BST, the remaining target in Path Sum, the largest value seen on the way down in Good Nodes, the path so far when all root-to-leaf paths are wanted. The cue in the wording is “ancestor”, “on the path from the root”, or a property that must hold against the whole tree rather than against the two children. The one-word reminder from Validate BST: range, not neighbours.

DFS and BFS: the system (9)

The whole traversal family: the one idea, how to choose, the five graph questions with the three shapes, the order to solve in, the traps, the complexity. The two answer cards are marked read: open a row only after your own attempt, the way you check the six lines after a DP problem.

DFS / BFSDFS and BFS in one idea: what is the only real choice?

One idea runs through every problem here: a traversal visits every node once, and the only choices are the order you visit in and what you carry along. Recursion or a stack gives depth-first (DFS): go as deep as you can, then back up. A queue gives breadth-first (BFS): finish everything at distance 1, then distance 2, and so on. Everything else is bookkeeping.

DFS / BFSWhich words in a problem pick BFS, DFS, topological order, or a cycle check?
The problem says Use Why
“shortest”, “fewest steps”, “minimum moves”, “nearest”, “level by level”, “each level” BFS the first time BFS reaches a node is by the fewest edges, and the queue holds exactly one level at a time
“is there a path”, “connected”, “count the islands or components”, “all paths”, “can be finished”, anything computed from the children upward DFS recursion carries the path for free, and the return value carries what the children found
a tree, and the answer depends on the subtrees DFS with the five questions hand up, empty, build, save, order
“order the tasks”, “prerequisites”, “which comes first” topological order a DFS or a BFS with in-degrees, on a directed graph
“is it a tree”, “cycle”, “connected and no cycle” DFS that carries the node it came from (the parent); union-find is the alternative to name, not to write in an undirected graph every edge is stored twice, so from B the edge back to A looks like a visited neighbour; that one is the parent and is ignored; any other visited neighbour is a real cycle

If both work, say so and pick the one whose bookkeeping is smaller. BFS costs the width of a level in memory, DFS costs the depth of the recursion.

DFS / BFSThe five graph questions to answer as comments, and the three shapes A, B, C?

A graph problem never says “graph”. It says grid, friends, prerequisites, cities, words. Before any code, answer these as comments:

NODES      what is a node, and how do I list its neighbours?
           (edges -> adjacency list; a grid cell -> the 4 cells around it; a word -> words one letter away)
VISITED    what marks a node as done, so I never visit it twice?
           (a set of ids; or write into the grid, for example flip '1' to '0')
START      where do I start, and how many times?
           (the given node once; every unvisited node, for components; every source at once, for multi-source)
CARRY      what travels with the node?
           (nothing; the depth; the parent, to allow one back edge; the path so far)
STOP       when am I done?
           (the queue or stack is empty; the target is found; every node has an order)

Three shapes cover the whole list:

Shape A, explore one component. Start somewhere, mark it, visit every neighbour you have not marked. Count how many times you had to start, or what you found inside. Islands, Clone Graph, Connected Components, Graph Valid Tree, Pacific Atlantic.

def dfs(node):
    mark node visited
    for each neighbour of node:
        if neighbour not visited:
            dfs(neighbour)

Shape B, order with dependencies (topological sort). A topological order is a line-up of every node in which every arrow points forward, so each thing comes after everything it depends on: socks before shoes, shirt before jacket. It exists only when there is no cycle, several orders are usually valid, and nothing is sorted by size; the word sort only means line up. Directed graph. Either count in-degrees, put every zero-in-degree node in a queue, pop and lower the in-degree of its targets (Kahn’s algorithm, a BFS); or DFS with three colors, white unseen, grey on the current path, black finished, where meeting grey means a cycle. If the order has fewer nodes than the graph, there was a cycle. Course Schedule, Alien Dictionary.

Shape C, fewest steps (BFS by levels). A queue, a visited set that you mark when you enqueue, and a loop that drains one level per step. The level counter is the distance. Level Order in a tree, Word Ladder, Rotting Oranges, any grid “minimum moves”.

queue = deque([start]); visited = {start}; steps = 0
while queue:
    for _ in range(len(queue)):          # exactly one level
        node = queue.popleft()
        if node is the target: return steps
        for nb in neighbours(node):
            if nb not in visited:
                visited.add(nb)           # mark on enqueue, never on dequeue
                queue.append(nb)
    steps += 1

“Every node has an order”, traced. Four courses: 0 needs nothing, 1 needs 0, 2 needs 0, 3 needs 1 and 2. In-degrees: 0 has 0, 1 has 1, 2 has 1, 3 has 2. The queue starts with 0. Pop 0, order = [0]; 1 and 2 drop to 0 and both join the queue. Pop 1, order = [0, 1]; 3 drops to 1. Pop 2, order = [0, 1, 2]; 3 drops to 0 and joins. Pop 3, order = [0, 1, 2, 3]. The queue is empty and 4 of 4 are placed: done, and that list is the order. Now also make 1 need 2 and 2 need 1. Their in-degrees become 2 and 2, they never reach 0, and the queue runs dry with order = [0] and 1 of 4 placed. Fewer than n placed means a cycle, so the courses cannot be finished.

DFS / BFSThe six traps, in the order they bite?
  • Marking visited on dequeue instead of enqueue in BFS: the same node enters the queue many times and the answer is still right, but the time is no longer O(V + E).
  • Forgetting to carry the parent in an undirected cycle check: the edge you just walked along points back at a visited node, so every edge looks like a cycle.
  • Using a visited set in a directed cycle check: a node visited by another path is not a cycle; only grey, on the current path, is.
  • Grid bounds and the already-flipped check in the wrong order: check bounds first, then the cell value.
  • Mutating the input grid when the problem forbids it: say it, then use a set.
  • Recursion depth on a 10^5-node chain: say “I would switch to an explicit stack”.

DFS / BFSTraversal complexity with its source, and the sentence to say?
  • Any traversal: O(V + E) time, every node once and every edge once from each side; for a grid that is O(rows × cols) with 4 edges per cell.
  • Space: the visited set O(V), plus the recursion depth or the queue: depth is the longest path for DFS, the widest level for BFS.
  • Topological sort: O(V + E) for both methods; the in-degree array is O(V).
  • Clone Graph: O(V + E) time, O(V) for the map.

The sentence to say: “every node and edge once, so O(V + E); the visited set is O(V), and the stack or queue is the depth or the width.”

Complexity: where it comes from (5)

Every complexity is a sentence with its source: the loop shape, the recursion tree, the number of states, or the cost per operation. Say the source before the big O.

COMPLEXITYLoops: how do you read the time off the code?

Sequential blocks add, nested blocks multiply. One pass over n is O(n). A loop over n with an inner loop over m is O(n·m). A loop whose body halves the problem is O(log n), so n binary searches are O(n log n). Sorting first costs O(n log n) and then a pass adds O(n), which stays O(n log n). Say it as a sentence: “one pass, constant work per element, so linear”.

COMPLEXITYRecursion and backtracking: where does 2^n or n! come from?

Count the recursion tree: nodes × work per node. Two choices per element and depth n give 2^n leaves (subsets, take or skip). n choices then n-1 then n-2 give n! leaves (permutations), and copying each answer adds a factor of n. A branching factor b and depth d give b^d. Space is the depth of the deepest path, the call stack, plus the current partial answer. Say it as: “two branches per element, depth n, so 2^n calls, each O(1), stack depth n”.

COMPLEXITYMemoization and DP: how does exponential become polynomial?

Memoization makes each distinct state computed once, so time is number of states × work per state. One index gives n states; an index and a remaining amount give n·target; two indices give n·m. Work per state is the number of choices: O(1) for take or skip, O(k) when k coins are tried, O(n) when all earlier states are scanned (LIS is n states × n scan = n²). Space is the table, reduced to O(1) or O(m) when only the last row or the last k values are needed.

COMPLEXITYData structures: the costs you add per operation?

Hash map and set: O(1) average per lookup or insert, so n lookups are O(n). Heap: push and pop are O(log k) on a heap of size k, so n pushes are O(n log k); building one from n items is O(n). Balanced BST and sorted containers: O(log n) per operation. Trie: one step per character, O(L) per word. Union-find with path compression and union by size: near O(1) per operation. Deque and monotonic stack: amortized O(1) per element because each element enters and leaves once. Graphs: every node and edge once is O(V+E); Dijkstra adds a heap step per edge, O((V+E) log V).

COMPLEXITYHow to say the complexity at the end of a problem?

One sentence with the source: “O(n log n) time: the sort dominates, then a single pass. O(n) space: the hash map of seen values; the output does not count.” Then the honest tail: the worst case you assumed (a skewed tree is O(n), not O(log n)) and the trade you would make if asked for less space.

PATTERN · CUES‘weighted’, ‘minimum cost’, ‘cheapest path’, ‘network delay’, ‘connect all points’, ‘k stops’Edge weights present; BFS no longer correct

Advanced Graph / Shortest Path. Weighted shortest paths, minimum spanning trees, ordering under constraints beyond simple BFS. Blind 75 touches this only through Alien Dictionary; know the shapes for follow-ups.

Ask yourself.

  • Are weights non-negative (Dijkstra) or possibly negative (Bellman-Ford)?
  • Single source or all pairs?
  • Is it really MST (connect everything cheaply) rather than shortest path?
  • Constraint on number of edges (k stops → BFS layers / Bellman-Ford k rounds)?

Core idea. Dijkstra: once a node is popped with the smallest tentative distance, that distance is final (non-negative weights). MST: the cheapest edge crossing a cut is safe.

Shape. Dijkstra: heap of (dist, node); pop; skip stale; relax neighbours. Prim: heap of edges from the tree. Kruskal: sort edges + union-find.

Complexity. Dijkstra O((V+E) log V) time: each node popped once and each edge relaxed once, each pop or relaxation a heap operation of log V. O(V+E) space: the adjacency list and the heap. Bellman-Ford O(V·E) time: V − 1 rounds, each relaxing all E edges. O(V) space: the distance array. Kruskal O(E log E) time: sorting the E edges costs E log E, then E union-find calls each cost nearly O(1). O(V) space: the parent and rank arrays.

Traps.

  • Using BFS with weights
  • Not skipping stale heap entries
  • Dijkstra with negative edges
  • Confusing shortest-path tree with MST

Use a different pattern when. Unweighted → BFS. DAG ordering → topological sort. Connectivity only → union-find.

PATTERN · CUES‘duplicate’, ‘anagram’, ‘group’, ‘frequency’, ‘top k’, ‘pair that sums to’Unsorted input and a hint that O(n log n) is not good enough · Need to look something up ‘have I seen X before?’ while scanning once

Arrays / Hashing. Any question about membership, counting, grouping, or finding pairs/complements in unsorted data where O(n) is expected.

Ask yourself.

  • What is the key I need O(1) lookup on: value, complement, canonical form, count?
  • Am I counting, grouping, or checking existence?
  • Is the value range small enough for an array instead of a hash map (bucket idea)?

Core idea. Trade space for time: a hash map turns a nested search into a constant-time lookup, so one pass suffices.

Shape. Scan once; for each element compute a key; consult/update the map; answer derived from the map at the end or on the fly.

Complexity. O(n) time: one pass over n elements, one O(1) average hash map lookup each. O(n·k) time when each key costs k to build, such as a count tuple, or O(n·k log k) when the key is a sorted string of length k. O(n) space: a hash map of up to n entries, or O(alphabet) for a fixed-size count array.

Traps.

  • Inserting before checking (element pairs with itself)
  • Unhashable keys (lists) — use tuples/strings
  • Forgetting a bounded value range enables counting sort / buckets
  • Sorting when the problem forbids or when O(n) is expected

Use a different pattern when. Input is sorted or must be processed in place with O(1) space → two pointers or in-place marking. Order/adjacency matters → sliding window or stack.

PATTERN · CUES‘all combinations’, ‘all subsets’, ‘exists a path’, ‘word in grid’, ‘unlimited reuse’, ‘no reuse’Exponential output or search space with pruning opportunities · Choices at each step, then undo

Backtracking. Enumerate all combinations/permutations/paths under constraints; search a grid for a word; build candidates incrementally and undo.

Ask yourself.

  • What is the state at each recursion (index, remaining target, path so far, visited)?
  • How do I avoid generating the same combination in a different order (start index)?
  • What prunes early (remaining < 0, prefix not in trie)?

Core idea. Choose → explore → un-choose; ordering constraints (start index) prevent duplicates; pruning cuts dead branches.

Shape. def bt(state): if goal: record; return; for choice in choices(state): apply; bt(new_state); undo.

Complexity. O(k^depth) time: k choices per level over depth levels give up to k^depth leaves. On grids, O(4·3^(L−1)) per start cell: 4 directions on the first step and 3 for each of the L − 1 later steps, since the path cannot step back. O(depth) space: one recursion frame and one path entry per level, output excluded.

Traps.

  • Forgetting to undo (unmark visited, pop path)
  • Generating permutations when combinations were asked
  • No pruning → TLE
  • Copying the path instead of referencing then copying on record

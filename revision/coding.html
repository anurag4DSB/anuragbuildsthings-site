DP: the six lines (4)

DPThe six lines to write as comments before any DP code? 
STATE       dp[...] = <a NUMBER or BOOLEAN in words>, e.g. "fewest coins to make amount a"
QUESTION    best (min/max) | possible (or) | count (+)
CHOICES     what can I do at this state? (take/skip · which coin · 1 or 2 steps · from above/left)
TRANSITION  each choice leads to which smaller state? combine with min/max, or, +
BASE        the smallest state whose answer I already know (dp[0] = ?)
ORDER       which states must exist before dp[i]? -> fill direction (forward, backward, by length)

DPQUESTION: which words mean best, possible or count, and what operator and starting value follow?
Words in the problem Kind Combine with Unknown starts as
minimum, fewest, cheapest, shortest best min inf (or amount+1)
maximum, most, largest, longest, max profit best max 0 or -inf
can, possible, exists, reachable possible or False
how many ways, count, number of paths count + 0

DPORDER: which direction do you fill, and the three loop rules for coins and knapsack?

If dp[i] uses smaller indices, fill forward; if it uses larger (suffix DPs), fill backward; 2-D fills row by row. Two rules that matter for coins/knapsack:

  • Reuse allowed (unlimited coins): iterate amounts forward within a coin.
  • Each item once (0/1 knapsack): iterate amounts backward so the item is not reused.
  • Counting: order matters (permutations) → amount loop outside, coins inside; order does not matter (combinations) → coins outside, amounts inside.

DPThe DP families and their shapes?
Family Shape
Fibonacci-style dp[i] from a few previous
Take / skip best(skip, take)
Unbounded choice dp[a] <- dp[a - choice]
Ending-at dp[i] = best ending at i, answer = max over i
Grid from above + from left
Two sequences match → diagonal, else drop one side
Expand / interval center or dp[l][r]

Patterns: cues to name (21)

PATTERN · CUES‘weighted’, ‘minimum cost’, ‘cheapest path’, ‘network delay’, ‘connect all points’, ‘k stops’ · Edge weights present; BFS no longer correct

Advanced Graph / Shortest Path. Weighted shortest paths, minimum spanning trees, ordering under constraints beyond simple BFS. Blind 75 touches this only through Alien Dictionary; know the shapes for follow-ups.

Ask yourself.

  • Are weights non-negative (Dijkstra) or possibly negative (Bellman-Ford)?
  • Single source or all pairs?
  • Is it really MST (connect everything cheaply) rather than shortest path?
  • Constraint on number of edges (k stops → BFS layers / Bellman-Ford k rounds)?

Core idea. Dijkstra: once a node is popped with the smallest tentative distance, that distance is final (non-negative weights). MST: the cheapest edge crossing a cut is safe.

Shape. Dijkstra: heap of (dist, node); pop; skip stale; relax neighbours. Prim: heap of edges from the tree. Kruskal: sort edges + union-find.

Complexity. Dijkstra O((V+E) log V); Bellman-Ford O(V·E); Kruskal O(E log E).

Traps.

  • Using BFS with weights
  • Not skipping stale heap entries
  • Dijkstra with negative edges
  • Confusing shortest-path tree with MST

Not this when. Unweighted → BFS. DAG ordering → topological sort. Connectivity only → union-find.

PATTERN · CUES‘duplicate’, ‘anagram’, ‘group’, ‘frequency’, ‘top k’, ‘pair that sums to’ · Unsorted input and a hint that O(n log n) is not good enough · Need to look something up ‘have I seen X before?’ while scanning once

Arrays / Hashing. Any question about membership, counting, grouping, or finding pairs/complements in unsorted data where O(n) is expected.

Ask yourself.

  • What is the key I need O(1) lookup on: value, complement, canonical form, count?
  • Am I counting, grouping, or checking existence?
  • Is the value range small enough for an array instead of a hash map (bucket idea)?

Core idea. Trade space for time: a hash map turns a nested search into a constant-time lookup, so one pass suffices.

Shape. Scan once; for each element compute a key; consult/update the map; answer derived from the map at the end or on the fly.

Complexity. Time O(n) (O(n·k) when the key costs k to build); space O(n) or O(alphabet).

Traps.

  • Inserting before checking (element pairs with itself)
  • Unhashable keys (lists) — use tuples/strings
  • Forgetting a bounded value range enables counting sort / buckets
  • Sorting when the problem forbids or when O(n) is expected

Not this when. Input is sorted or must be processed in place with O(1) space → two pointers or in-place marking. Order/adjacency matters → sliding window or stack.

PATTERN · CUES‘all combinations’, ‘all subsets’, ‘exists a path’, ‘word in grid’, ‘unlimited reuse’, ‘no reuse’ · Exponential output or search space with pruning opportunities · Choices at each step, then undo

Backtracking. Enumerate all combinations/permutations/paths under constraints; search a grid for a word; build candidates incrementally and undo.

Ask yourself.

  • What is the state at each recursion (index, remaining target, path so far, visited)?
  • How do I avoid generating the same combination in a different order (start index)?
  • What prunes early (remaining < 0, prefix not in trie)?

Core idea. Choose → explore → un-choose; ordering constraints (start index) prevent duplicates; pruning cuts dead branches.

Shape. def bt(state): if goal: record; return; for choice in choices(state): apply; bt(new_state); undo.

Complexity. Time exponential (O(k^depth) or O(4·3^(L-1)) on grids); space O(depth).

Traps.

  • Forgetting to undo (unmark visited, pop path)
  • Generating permutations when combinations were asked
  • No pruning → TLE
  • Copying the path instead of referencing then copying on record

Not this when. Counting the number of ways (not listing them) → DP. Shortest path → BFS. Optimal value with overlapping subproblems → DP.

PATTERN · CUES‘sorted’, ‘rotated’, ‘O(log n)’, ‘find minimum/target’, ‘first/last position’ · A yes/no predicate that is false…false,true…true over the search space (binary search on the answer) · Search space is a numeric range, not just an array

Binary Search. Sorted or rotated-sorted data, or any monotonic predicate over a range where the answer can be found by halving.

Ask yourself.

  • What is monotonic here — the values, or a predicate on the index/answer?
  • After comparing mid, which half can I prove does NOT contain the answer?
  • Am I searching for existence, a boundary (first true), or an extremum?

Core idea. Each comparison halves the space while preserving the invariant that the answer stays inside [lo, hi].

Shape. lo, hi = bounds; while lo < hi (or <=): mid; test; move lo or hi so the invariant holds; return lo/hi with a final check.

Complexity. Time O(log n); space O(1).

Traps.

  • Infinite loop from mid rounding with lo = mid
  • Wrong invariant for inclusive vs exclusive hi
  • Rotated arrays: identify the sorted half before deciding
  • Duplicates break the ‘which half is sorted’ test

Not this when. Data unsorted with no monotonic predicate → hashing/sorting first. Need all matches, not one → scan or two pointers.

PATTERN · CUES‘BST’, ‘binary search tree’, ‘kth smallest/largest’, ‘sorted order’, ‘lowest common ancestor’ with BST · Left < node < right must hold for entire subtrees

BST / Inorder. Binary search tree questions: kth smallest, validation, LCA, range queries — the ordering property is the tool.

Ask yourself.

  • Does inorder traversal (sorted sequence) solve it directly?
  • Can I use the BST property to descend in O(h) instead of visiting everything?
  • What bounds must each node satisfy relative to all ancestors?

Core idea. Inorder of a BST is sorted; comparisons at a node tell you which subtree contains what you want.

Shape. Iterative inorder with a stack (stop early at k); or descend from root comparing values; or DFS carrying (low, high) bounds.

Complexity. Time O(h) for descents, O(h + k) for kth via inorder, O(n) for full validation; space O(h).

Traps.

  • Validating only against direct children
  • Equal values (strict vs non-strict)
  • Using ±infinity sentinels incorrectly
  • Collecting the whole inorder list when early stop was possible

Not this when. Tree is not a BST → general DFS/BFS. Need frequent kth queries with updates → augmented tree/order statistics (out of scope).

PATTERN · CUES‘number of ways’, ‘minimum/maximum … ending at’, ‘can be segmented’, ‘fewest coins’, ‘non-adjacent’, ‘decode’, ‘longest increasing subsequence’ · Recursion with repeated states; greedy is wrong · Answer builds from smaller prefixes or smaller amounts

1-D Dynamic Programming. Optimal value or count over a sequence/amount where the answer for position i depends on a few earlier positions; overlapping subproblems. Before any DP attempt: the six questions in the DP cheat sheet.

Ask yourself.

  • What is dp[i] in one sentence (ways to reach i? best ending at i? feasible prefix i?)
  • What are the last-step choices that lead to i, and from which states?
  • Base cases and answer location (dp[n] or max over dp)?
  • Can I roll the array to O(1) space?

Core idea. Define the state so the last decision is local; the recurrence combines a constant (or small) number of earlier states; memoise or fill bottom-up.

Shape. dp array sized n+1 (or amount+1) → base cases → for i in range: dp[i] = combine(dp[i−k] for valid k) → return dp[n] / max.

Complexity. Time O(n·choices) (O(n²) for LIS-style, O(amount·coins) for knapsack-like); space O(n) or O(1) rolled.

Traps.

  • Wrong state definition (ending-at vs up-to)
  • Greedy shortcut that fails (coin change)
  • Off-by-one on indices with a padded dp[0]
  • Forgetting the min/max tracking pair when negatives flip signs (product problems)

Not this when. Two sequences or a grid → 2-D DP. Need to enumerate solutions → backtracking. Local choice provably safe → greedy.

PATTERN · CUES‘two strings’, ‘common subsequence’, ‘grid paths’, ‘m × n’, ‘edit’, ‘match’ · Recurrence depends on (i−1, j), (i, j−1), (i−1, j−1)

2-D Dynamic Programming. Two sequences (LCS, edit distance) or a grid (paths) where the state needs two indices.

Ask yourself.

  • What does dp[i][j] mean (prefixes of length i and j? cell (i, j)?)
  • What happens when the current characters match vs not?
  • Can I keep one row (previous) to reduce space?
  • Is there a closed form (combinatorics) for the grid case?

Core idea. Matching last elements extends the diagonal state; otherwise take the best of dropping one side; grids sum the two arrivals.

Shape. dp with (m+1)×(n+1) padding → fill row by row → dp[m][n]; roll rows for O(n) space.

Complexity. Time O(m·n); space O(m·n) or O(min(m, n)).

Traps.

  • Subsequence vs substring confusion
  • Padding off-by-one
  • Wrong combination for mismatch (max vs sum)
  • Trying 1-D when two indices are genuinely needed

Not this when. Single sequence → 1-D DP. Palindromes in one string → expand-around-center is usually simpler than 2-D DP.

PATTERN · CUES‘connected’, ‘islands’, ‘reachable’, ‘clone’, ‘grid of 0/1’, ‘neighbors’, ‘shortest number of steps’ · Nodes and edges are explicit, or implicit in a grid

Graph DFS / BFS. Connectivity, components, reachability, flood fill on grids, cloning, shortest path in unweighted graphs.

Ask yourself.

  • What is a node and what is an edge (grid cells with 4-neighbours)?
  • DFS (any path, components) or BFS (shortest path, levels)?
  • How do I mark visited — a set, or in place on the grid?
  • Can I start from the borders/targets instead of every cell (multi-source, reverse search)?

Core idea. Each node is discovered once; a visited set (or in-place marking) guarantees O(V+E).

Shape. for each unvisited start: traverse (stack/recursion or queue), mark visited, collect; count/aggregate per traversal.

Complexity. Time O(V+E) = O(m·n) on grids; space O(V) for visited/queue.

Traps.

  • Recursion depth on large grids (use iterative or BFS)
  • Diagonal vs 4-directional adjacency
  • Forgetting the visited map for cycles when cloning
  • Simulating from every source instead of reversing from the targets

Not this when. Ordering constraints → topological sort. Weighted shortest path → Dijkstra. Only components count without traversal → union-find.

PATTERN · CUES‘maximum/minimum with a simple structure’, ‘can reach’, ‘minimum removals’, ‘max profit one transaction’, ‘maximum subarray’ · An exchange argument works: swapping the greedy choice for any other never helps

Greedy. Local choice that is provably safe: earliest finishing interval, farthest reach, running max/min, Kadane-style ‘reset when negative’.

Ask yourself.

  • What quantity, if I always pick the extreme, can never be worse (exchange argument)?
  • Is there a running summary (max reach, min price, current sum) that decides each step?
  • Would DP be equivalent but slower — can I explain why greedy is safe?

Core idea. A locally optimal step preserves the possibility of a globally optimal completion; one linear scan with a running summary suffices.

Shape. Sort if needed → scan → maintain summary (best so far, current run, farthest reach) → update answer each step.

Complexity. Time O(n) or O(n log n) with sort; space O(1).

Traps.

  • Assuming greedy works without the exchange argument (coin change is the classic failure)
  • Initialising with 0 when all values may be negative
  • Sorting by the wrong key
  • Confusing with the harder variant (Jump Game II, multiple transactions)

Not this when. Choices interact and local optimum can be wrong → DP. Need all solutions → backtracking.

PATTERN · CUES‘k smallest/largest’, ‘k sorted lists’, ‘median of stream’, ‘minimum rooms’, ‘schedule’, ‘most frequent’ · Need extract-min/max in O(log n) while inserting · Only the extremes matter, not full sorted order

Heap / Priority Queue. Repeatedly need the current min/max among a changing set: k-way merge, top-k, medians, scheduling by earliest end.

Ask yourself.

  • Do I need the full sort, or just the extreme repeatedly?
  • Min-heap or max-heap, and of what tuple (with tie-breakers)?
  • Would two heaps (low/high halves) or a heap of size k solve it?

Core idea. A heap keeps the extreme available in O(1) and restores order in O(log n) per change; a size-k heap keeps the k best seen so far.

Shape. Build heap of initial items → loop: pop extreme, process, push replacement/new items → answer from heap contents or pop sequence.

Complexity. Time O(n log k) or O(n log n); space O(k) or O(n).

Traps.

  • Python heapq is a min-heap: negate for max
  • Tuple comparison hitting incomparable objects (add an index tie-breaker)
  • Rebalancing direction in two-heap median
  • Using a heap when bucket counting gives O(n)

Not this when. Value range small → bucket sort. Need arbitrary deletes or order statistics → balanced BST/sorted container. Only one pass extreme → single variable.

PATTERN · CUES‘intervals’, ‘meetings’, ‘overlapping’, ‘merge’, ‘rooms’, ‘non-overlapping’ · Sorting by start or by end makes the problem a single sweep

Intervals. Ranges with start/end: merge, insert, count overlaps, minimum removals, minimum rooms, can-attend.

Ask yourself.

  • Sort by start (merging, overlap checks) or by end (greedy selection)?
  • What is the overlap condition exactly (inclusive ends?)
  • Do I need the maximum concurrent count (sweep line / two sorted arrays / heap)?

Core idea. After sorting, each interval interacts only with the current merged/last-kept interval (or the earliest-ending active one).

Shape. Sort → iterate → compare with last kept: merge/extend, skip, or count → return result.

Complexity. Time O(n log n); space O(n) output or O(1).

Traps.

  • Not taking max of ends when merging
  • Touching intervals treated as overlapping or not — clarify
  • Greedy by wrong key (keep longest instead of earliest end)
  • Tie order in sweep line (end before start at equal time when touching is allowed)

Not this when. Intervals on a tree/graph → different structure. Need dynamic insert/query of overlaps → interval tree / segment tree (rare in interviews).

PATTERN · CUES‘linked list’, ‘in place’, ‘O(1) space’, ‘reverse’, ‘merge’, ‘cycle’, ‘nth from end’ · The task decomposes into: find middle, reverse, merge, two-pointer gap · Node identity matters more than values

Linked List Pointer Manipulation. Singly linked list rewiring: reverse, merge, find middle, detect cycle, remove nth-from-end, reorder — usually in O(1) extra space.

Ask yourself.

  • Which of the four primitives (reverse, merge, middle via fast/slow, gap pointers) does this compose?
  • Do I need a dummy head to avoid head/edge special cases?
  • Which pointer must be saved before I overwrite a .next?

Core idea. Never lose a reference: save next before rewiring; a dummy head makes head-removal ordinary.

Shape. dummy → pointers (prev/cur/next or slow/fast) → loop with explicit save-then-rewire → return dummy.next.

Complexity. Time O(n); space O(1) iterative (O(n) recursive stack).

Traps.

  • Losing the rest of the list by rewiring before saving next
  • Not cutting the first half’s tail before reversing the second half (creates a cycle)
  • Null checks on fast.next
  • Off-by-one in the gap for nth-from-end

Not this when. Random access or sorting needed → arrays. Values (not structure) matter → hashing is acceptable when space is allowed.

PATTERN · CUES‘rotate the image’, ‘spiral order’, ‘set row and column to zero’, ‘in place’, ‘O(1) extra space’ · The answer is about index gymnastics, not algorithms

Matrix Traversal. In-place matrix transforms and ordered traversals: rotate, spiral, set zeroes, transpose; boundary bookkeeping is the whole problem.

Ask yourself.

  • Can the transform decompose into simpler in-place operations (transpose + reverse)?
  • What four boundaries shrink each round, and when must I stop early?
  • Where can I store flags for free (first row/column) without corrupting them prematurely?

Core idea. Keep explicit boundaries/markers and update them in a fixed order so each cell is touched a constant number of times.

Shape. Rotate: transpose then reverse rows. Spiral: top/bottom/left/right, four passes, shrink, guard against double-visit. Zeroes: mark first row/col, apply, then fix first row/col.

Complexity. Time O(m·n); space O(1).

Traps.

  • Double-visiting the last row/column in spiral for non-square matrices
  • Overwriting marker row/column before reading it
  • Rotating counter-clockwise by accident
  • Layer-by-layer index errors when transpose+reverse was available

Not this when. Grid connectivity → graph DFS/BFS. Counting paths → 2-D DP. Searching words → backtracking.

PATTERN · CUES‘substring’, ‘subarray’, ‘contiguous’, ‘window’, ‘at most k’, ‘without repeating’, ‘containing all’ · A validity condition that can be updated incrementally when one element enters or leaves · O(n) expected over strings/arrays

Sliding Window. ‘Longest/shortest/max/min contiguous subarray or substring satisfying a condition’ over a linear sequence.

Ask yourself.

  • What makes a window valid, and can I check that in O(1) with counters?
  • Fixed size or variable size window?
  • When the window becomes invalid, how far must the left edge move — one step, or jump?

Core idea. Maintain a window and O(1)-updatable summary (counts, max, distinct count) so that each element enters once and leaves once.

Shape. right expands one at a time; update summary; while invalid: shrink left and update; record best when valid (longest: after shrink; shortest: while valid).

Complexity. Time O(n) (each index enters and leaves once); space O(alphabet) or O(k).

Traps.

  • Shrinking by one when a jump (via last-seen index) is correct
  • Recording the answer at the wrong moment (before/after fixing validity)
  • For ‘shortest’ problems, forgetting to shrink while still valid
  • Windows over negative numbers break monotonicity (then prefix sums, not windows)

Not this when. Elements not contiguous → DP/hashing. Condition not incrementally maintainable (e.g., median) → different structure. Negative numbers with sum constraint → prefix sums + hashing.

PATTERN · CUES‘valid parentheses’, ‘balanced’, ‘nested’, ‘undo’, ‘evaluate expression’, ‘next greater/smaller’ · The answer for an element depends on the nearest previous element with some property · Need to process in LIFO order

Stack. Matching/nesting, ‘most recent unmatched thing’, next-greater-element, or simulating recursion iteratively.

Ask yourself.

  • What is the most recent open item that the current item must pair with?
  • Should the stack hold values or indices (indices when distances/spans matter)?
  • Is a monotonic stack (increasing/decreasing) what I need for ‘next greater’?

Core idea. The stack holds exactly the unresolved candidates; the top is always the one the current element interacts with.

Shape. For each element: pop while top is resolved by it (recording answers); push the element; at the end handle leftovers.

Complexity. Time O(n) (each element pushed/popped once); space O(n).

Traps.

  • Popping from an empty stack
  • Not checking the stack is empty at the end (unmatched openers)
  • Storing values when indices are needed
  • Confusing which direction a monotonic stack should be monotonic

Not this when. FIFO order needed → queue/BFS. Need min/max over a sliding window → deque. Random access needed → arrays.

PATTERN · CUES‘prerequisites’, ‘dependencies’, ‘order’, ‘schedule’, ‘alien dictionary’, ‘build order’ · Directed edges meaning ‘must come before’ · Ask ‘is there a cycle?’ in a directed graph

Topological Sort. Directed dependencies: can all tasks finish, in what order, is there a cycle, derive an order from pairwise constraints.

Ask yourself.

  • Where do the edges come from (given, or derived from adjacent comparisons)?
  • Kahn’s (indegree + queue) or DFS with three colours?
  • What does a cycle mean for the answer (impossible / empty)?
  • Are there nodes with no edges that still need to appear?

Core idea. A node can be emitted once all its predecessors are; if some nodes never reach indegree 0, there is a cycle.

Shape. Build adjacency + indegree → queue all indegree-0 → pop, emit, decrement neighbours, push zeros → emitted count == n else cycle.

Complexity. Time O(V+E); space O(V+E).

Traps.

  • Edge direction reversed
  • Plain visited set (cannot distinguish cycle from cross edge) — use 3 colours
  • Forgetting isolated nodes
  • Alien dictionary: prefix case (‘abc’ before ‘ab’) is invalid; multiple valid orders

Not this when. Undirected graph → components/union-find. Need shortest path → BFS/Dijkstra. Order not constrained → sorting.

PATTERN · CUES‘level order’, ‘level by level’, ‘each level’, ‘minimum depth’, ‘width’ · Need nodes grouped by distance from the root

Tree BFS. Level-order questions: levels as lists, right-side view, minimum depth, zigzag, connecting nodes on the same level.

Ask yourself.

  • How do I delimit one level in the queue (snapshot len(queue))?
  • Do I need per-level aggregation or just order?
  • Would DFS with a depth parameter be equally simple?

Core idea. A queue processes nodes in distance order; processing exactly len(queue) nodes handles one level.

Shape. queue=[root]; while queue: size=len(queue); for _ in range(size): pop, record, push children; append level result.

Complexity. Time O(n); space O(w) where w is max width (up to n/2).

Traps.

  • Not snapshotting the level size
  • Pushing None children
  • Using BFS when the problem is really per-subtree (DFS simpler)

Not this when. Per-subtree values → DFS. Sorted order from BST → inorder DFS.

PATTERN · CUES‘binary tree’, ‘subtree’, ‘path’, ‘depth/height’, ‘same/identical’, ‘invert’, ‘maximum path sum’ · The answer at a node depends only on answers from its children (post-order) · Or constraints flow down from ancestors (pre-order with parameters)

Tree DFS. Anything computed per subtree: depth, sums, validity, equality, paths, invert, construct. Recursion that returns a value up.

Ask yourself.

  • What does a subtree need to return to its parent (one number? a pair? a boolean?)
  • What information flows down (bounds, path so far)?
  • Is the global answer different from the returned value (path sum problems)?

Core idea. Post-order recursion: solve children first, combine at the node; keep a separate global when the answer is not what you pass upward.

Shape. def dfs(node): if not node: base; L = dfs(left); R = dfs(right); update global; return combined-for-parent.

Complexity. Time O(n); space O(h) recursion (worst O(n) skewed).

Traps.

  • Returning the two-branch path upward (only one branch can continue)
  • Not clamping negative contributions to 0 where allowed
  • Checking only immediate children for BST validity instead of propagated bounds
  • Recursion depth on skewed trees (use iterative if huge)

Not this when. Need level-by-level order or shortest path in an unweighted tree → BFS. Need sorted order from a BST → inorder.

PATTERN · CUES‘prefix’, ‘autocomplete’, ‘dictionary of words’, ‘startsWith’, ‘many words on a grid’ · Repeated prefix checks that would re-scan strings

Trie. Prefix operations over many words: insert/search/startsWith, wildcard search, finding all dictionary words in a grid.

Ask yourself.

  • What does a node store — children map and an end-of-word flag (or the word itself)?
  • How does a wildcard branch (DFS over all children)?
  • Can the trie prune a search (stop when no child matches)?

Core idea. Shared prefixes are stored once; walking one character per level makes prefix queries O(L).

Shape. Node = {children: {}, end: bool}; insert walks/creates; search walks; startsWith walks without end check; DFS for wildcards.

Complexity. Time O(L) per operation; space O(total characters).

Traps.

  • Confusing search (needs end flag) with startsWith
  • Not pruning found words / dead leaves in grid search (TLE)
  • Duplicate results when a word is found via two paths
  • Recursion depth for long words is fine; grid DFS unmark is the usual bug

Not this when. Single string matching → hashing/KMP. Suffix queries → suffix structures. Few words → a set is enough.

PATTERN · CUES‘sorted array’, ‘palindrome’, ‘pair/triplet’, ‘container’, ‘in place’ · A monotonic relationship: moving one pointer changes the quantity in a predictable direction · Need O(1) extra space

Two Pointers. Sorted (or sortable) sequences, palindromes, or ‘pick two elements’ questions where a brute-force pair scan is O(n²).

Ask yourself.

  • If I fix one end, can I discard a whole side of candidates by a single comparison?
  • Do the pointers converge (ends inward) or chase (same direction, fast/slow)?
  • Can sorting first unlock the monotonicity?

Core idea. Each pointer move provably discards candidates that cannot beat the current best, so every element is visited O(1) times.

Shape. Sort if needed → place pointers → loop while they have not crossed → compare, record, move the pointer whose move can improve the answer.

Complexity. Time O(n) after an O(n log n) sort; space O(1).

Traps.

  • Moving the wrong pointer (the one whose move cannot improve the result)
  • Duplicate handling in k-sum problems
  • Off-by-one on the crossing condition
  • Forgetting to skip invalid characters (palindromes)

Not this when. Need to consider a contiguous range with a running property → sliding window. Need arbitrary lookups in unsorted data → hashing.

PATTERN · CUES‘connected components’, ‘valid tree’, ‘redundant connection’, ‘union’, ‘group’ · Edges arrive as a list and only connectivity matters, not paths · Undirected

Union Find (Disjoint Set Union). Dynamic connectivity: count components, detect a cycle in an undirected graph, check if edges form a tree, group equivalent items.

Ask yourself.

  • Does each successful union reduce the component count by one?
  • Does a failed union (same root) mean a cycle?
  • Do I need path compression/union by rank (yes, it is two lines)?

Core idea. Each set has one representative; find returns it in near-O(1) amortised; union merges sets or reveals a cycle.

Shape. parent=[i]; find with path compression; union returns False if same root; components = n − successful unions.

Complexity. Time O((V+E) α(n)) ≈ linear; space O(V).

Traps.

  • No path compression (still passes but say why it matters)

RECOGNITION · MEDIUMLongest Repeating Character Replacement: ‘replace at most k characters’, ‘longest substring with the same letter’

Pattern. Sliding Window + max frequency

Ask yourself.

  • When is a window fixable with k replacements? (length − most frequent ≤ k)
  • Does the max frequency need to decrease when the window shrinks?

The leap. A window is valid iff its length minus its most frequent count is ≤ k; the historical max frequency never needs decrementing to get the right answer.

Complexity. O(n) time, O(26) space.

Trap. Recomputing the max on every step (acceptable at 26) or shrinking the window incorrectly.

RECOGNITION · MEDIUMLongest Substring Without Repeating Characters: ‘longest substring’, ‘without repeating characters’

Pattern. Sliding Window (variable) + last-seen map

Ask yourself.

  • What makes the window valid, and can I check it in O(1)?
  • When a repeat enters, how far must the left edge jump?

The leap. Maintain a window of unique characters; on a repeat, move left just past the previous occurrence (never backwards).

Complexity. O(n) time, O(alphabet) space.

Trap. Moving left by one instead of jumping; forgetting max(left, last_seen + 1).

RECOGNITION · HARDMinimum Window Substring: ‘minimum window of s containing every character of t’, counts matter, ‘hard’

Pattern. Sliding Window (need/have counters)

Ask yourself.

  • How do I know in O(1) that the window satisfies t? (a formed/satisfied counter)
  • Expand until formed, then shrink while still formed — what updates on each move?

The leap. Track need counts vs have counts and the number of fully satisfied characters; expand right until satisfied, shrink left while satisfied, record the smallest.

Complexity. O(|s| + |t|) time, O(alphabet) space.

Trap. Mishandling duplicate characters in t; recording the answer before the window is fully formed.

Recognition: Stack (1)

RECOGNITION · EASYValid Parentheses: ‘brackets’, ‘valid/balanced’, ‘closed in the correct order’

Pattern. Stack (matching)

Ask yourself.

  • What must the most recent unmatched opener be when a closer arrives?
  • What is left on the stack at the end?

The leap. LIFO matching: push openers, pop and compare on closers; the stack must be empty at the end.

Complexity. O(n) time, O(n) space.

Trap. Popping an empty stack; forgetting leftover openers.

Recognition: Trees (11)

RECOGNITION · MEDIUMConstruct Binary Tree From Preorder And Inorder Traversal: ‘preorder and inorder’, ‘construct the tree’

Pattern. Divide & conquer on traversal arrays

Ask yourself.

  • What does the first preorder element tell me?
  • How does that element’s position in inorder split left and right subtree sizes?

The leap. Preorder gives the root; its index in inorder gives the left size; recurse on the corresponding ranges using an index map.

Complexity. O(n) time with a value→index map (O(n²) with linear searches), O(n) space.

Trap. Slicing arrays (hidden O(n²) copies); wrong preorder offset for the right subtree.

RECOGNITION · HARDBinary Tree Maximum Path Sum: ‘path between any two nodes’, ‘maximum sum’, negative values present, ‘hard’

Pattern. Tree DFS post-order with two meanings

Ask yourself.

  • What does a subtree hand upward (one branch) versus what does it record globally (both branches)?
  • What do I do with negative contributions?

The leap. Return the best single-branch gain (floored at zero) to the parent while updating a global best with left + right + node.

Complexity. O(n) time, O(h) space.

Trap. Passing both branches upward; not clamping negatives.

RECOGNITION · EASYMaximum Depth of Binary Tree: ‘maximum depth’, ‘longest root-to-leaf path’

Pattern. Tree DFS (post-order height)

Ask yourself.

  • What single number does each subtree return to its parent?

The leap. height(node) = 1 + max(height(left), height(right)).

Complexity. O(n) time, O(h) space.

Trap. Counting edges vs nodes; recursion depth on skewed trees.

RECOGNITION · EASYInvert Binary Tree: ‘invert’, ‘mirror’, ‘swap left and right’

Pattern. Tree DFS (local swap)

Ask yourself.

  • Is the operation purely local to each node?

The leap. Swap the children at each node and recurse; any traversal order works.

Complexity. O(n) time, O(h) space.

Trap. None serious — this is a warm-up to make recursion automatic.

RECOGNITION · MEDIUMKth Smallest Element In a Bst: ‘kth smallest’, ‘BST’

Pattern. BST inorder traversal (iterative, early stop)

Ask yourself.

  • What order does inorder produce?
  • Can I stop after k nodes instead of traversing everything?

The leap. Inorder of a BST is sorted; an explicit stack lets you stop at the kth visit.

Complexity. O(h + k) time, O(h) space.

Trap. Collecting the whole inorder list (correct but O(n)); off-by-one on k.

RECOGNITION · MEDIUMBinary Tree Level Order Traversal: ‘level order’, ‘return values per level’

Pattern. Tree BFS (level by level)

Ask yourself.

  • How do I know where one level ends inside the queue?

The leap. Process exactly len(queue) nodes per round; each round is one level.

Complexity. O(n) time, O(w) space.

Trap. Not snapshotting the queue size before the inner loop.

RECOGNITION · MEDIUMLowest Common Ancestor of a Binary Search Tree: ‘lowest common ancestor’, ‘BST’

Pattern. BST property walk

Ask yourself.

  • How does the ordering tell me whether both nodes lie left, right, or split?

The leap. Walk down from the root: both smaller → left, both larger → right, otherwise the current node is the split point.

Complexity. O(h) time, O(1) space iteratively.

Trap. Using the general-tree LCA algorithm (works but ignores the property); forgetting a node can be its own ancestor.

RECOGNITION · EASYSame Tree: ‘structurally identical and same values’

Pattern. Tree DFS (lockstep traversal)

Ask yourself.

  • What are the base cases when one or both nodes are null?

The leap. Recurse on both trees simultaneously; equality of structure and value at every node.

Complexity. O(n) time, O(h) space.

Trap. Comparing values before null checks.

RECOGNITION · HARDSerialize And Deserialize Binary Tree: ‘serialize / deserialize’, ‘any binary tree’, ‘design’

Pattern. Tree DFS preorder with null markers

Ask yourself.

  • How do I mark missing children so the structure is unambiguous?
  • Which traversal is easiest to invert with a token iterator?

The leap. Preorder with explicit null markers is self-delimiting; deserialisation consumes tokens in the same order.

Complexity. O(n) time, O(n) space.

Trap. Delimiters versus multi-digit or negative values; recursion depth.

RECOGNITION · EASYSubtree of Another Tree: ‘subRoot is a subtree of root’, ‘same structure and values’

Pattern. Tree DFS with Same Tree as a helper

Ask yourself.

  • Where could a match start?
  • Can I reuse Same Tree at every candidate node?

The leap. At each node of the big tree, test identity against subRoot with the Same Tree check.

Complexity. O(n·m) time, O(h) space (serialisation + string matching can do better).

Trap. Accepting a partial match; forgetting the empty-subtree edge semantics.

RECOGNITION · MEDIUMValidate Binary Search Tree: ‘valid BST’, ‘left subtree only smaller, right subtree only larger’

Pattern. Tree DFS with propagated bounds

Ask yourself.

  • Is checking against immediate children enough? (no)
  • What bounds does each node inherit from its ancestors?

The leap. Every node must lie strictly inside an (low, high) interval inherited from above; or the inorder sequence must be strictly increasing.

Complexity. O(n) time, O(h) space.

Trap. Comparing only with children; equal values; sentinel handling for the bounds.

Recognition: Tries (3)

RECOGNITION · MEDIUMDesign Add And Search Words Data Structure: ‘search with’.’ matching any letter’

Pattern. Trie + DFS for wildcards

Ask yourself.

  • What must happen at a ‘.’ character?
  • Where does the end-of-word check happen?

The leap. Walk the trie; on a wildcard, branch into every child (backtracking over the trie).

Complexity. O(26^dots · L) worst case per search, O(total characters) space.

Trap. Returning only the first child’s result; ignoring the end flag at the last character.

RECOGNITION · MEDIUMImplement Trie Prefix Tree: ‘insert / search / startsWith’, ‘prefix tree’

Pattern. Trie

Ask yourself.

  • What does a node store?
  • How is end-of-word distinguished from a prefix?

The leap. Children map per node plus an end flag; every operation walks one character per level.

Complexity. O(L) per operation, O(total characters) space.

Trap. Returning true from search when only a prefix exists; conflating search and startsWith.

RECOGNITION · HARDWord Search II: ‘find all words from a list in the grid’, ‘hard’

Pattern. Trie + grid backtracking with pruning

Ask yourself.

  • Why does running Word Search per word explode?
  • How can a trie prune the grid DFS?

The leap. Build a trie of the words and DFS the grid while walking the trie simultaneously; stop at dead nodes, collect at word ends, and prune found words.

Complexity. Bounded by O(m·n·4·3^(L−1)) but far less with pruning; O(total characters) space.

Trap. Duplicate results; not pruning found words or dead leaves (time limit); forgetting to unmark cells.

Recognition: Two Pointers (3)

RECOGNITION · EASYValid Palindrome: ‘reads the same forward and backward’, ‘ignore non-alphanumeric’, ‘case-insensitive’

Pattern. Two Pointers (converging)

Ask yourself.

  • Which characters count, and can I skip the others in place?
  • Do I need to build a cleaned string at all?

The leap. Converge from both ends, skipping invalid characters, comparing normalised characters.

Complexity. O(n) time, O(1) space.

Trap. Allocating a filtered copy (fine, but O(n) space); mishandling the skip loop bounds.

RECOGNITION · MEDIUMContainer With Most Water: ‘two lines form a container’, ‘most water’, heights array

Pattern. Two Pointers (greedy shrink)

Ask yourself.

  • Which side limits the area — the shorter line or the taller?
  • Why can moving the taller side never increase the area?

The leap. Area is bounded by the shorter line; moving the shorter pointer inward is the only move that can improve the result.

Complexity. O(n) time, O(1) space.

Trap. Brute-force pairs; moving the taller pointer.

RECOGNITION · MEDIUM3Sum: ‘triplets that sum to zero’, ‘no duplicate triplets’

Pattern. Sort + two pointers

Ask yourself.

  • After sorting and fixing one element, is this Two Sum on a sorted array?
  • Where exactly do duplicates get skipped (anchor level and pointer level)?

The leap. Sort; for each anchor, converge two pointers on the remainder; skip equal neighbours at every level to avoid duplicate triplets.

Complexity. O(n²) time, O(1) extra space (ignoring output).

Trap. Forgetting to move both pointers after a hit; skipping duplicates only at the anchor.
